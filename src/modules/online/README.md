# Online low-code engine

Phase 2 adds tenant-scoped PostgreSQL metadata persistence for Definition, Revision, Field, Index, Relation, View, Action, Policy, WorkflowBinding, Release, SchemaChange, and TestSession records. It intentionally has no in-memory fallback: Online metadata routes fail closed when PostgreSQL is unavailable.

The protected management lifecycle is now available: create a Definition with its initial Draft Revision, edit Definition/Draft metadata using `expectedLockVersion`, validate the Draft, create a semantic Schema Plan, publish an immutable SHA-256-protected Release snapshot, and atomically point the Definition back to a prior Release. Published revisions are immutable; publication creates a separate next Draft Revision.

Phase 3 accepts only structured Model IR and generates deterministic field/index operations with a fingerprint and risk level. A plan never accepts, creates, stores, or exposes executable SQL. Changing a Draft model supersedes its open plans; low-risk plans can be approved with an audited note, while destructive and unsupported plans cannot be approved. DDL execution and `/apply` routes are deliberately disabled. A release is blocked if it still has a planned schema change that requires execution.

Phase 4 adds a protected browser-based Online Test baseline for published `SINGLE` Definitions using `GENERIC_RECORD` storage. Starting a test resolves the current Published Release, verifies its checksum, creates an actor-owned sandbox session, and validates CRUD values solely against that immutable Release model. Each record is tenant-, definition-, release-, and test-session-scoped; Draft revisions and dynamic business tables are never read or written by this path. `TREE` and `MASTER_DETAIL` Runtime remain disabled until their transaction, hierarchy, and relation semantics are implemented.

Phase 5 adds safe Puck presentation views. Drafts may store only registered Online components and controlled Definition/view/field/action bindings in `online_view`; the server validates size, depth, component keys, props, prototype keys, and Draft field/action references. Saving a Draft invalidates validation, validation fingerprints the normalized views, and publish checksums the normalized views inside the immutable Release snapshot before cloning them to the next Draft. Online Test renders a preview only from that compiled Release snapshot and uses the same component config as the editor. No view metadata may contain an endpoint URL, HTML, JavaScript, SQL, event handler, or executable behavior.

Puck rendering is presentation-only. The available Online Test remains sandbox-only `SINGLE + GENERIC_RECORD`; production Runtime CRUD, `TREE`/`MASTER_DETAIL`, workflow execution, report/chart/dashboard queries, and code generation remain disabled until their separate policy, audit, and release-resolver boundaries are implemented. The `online_record` migration is intentionally present but not deployed by this module; deploy it only through an approved staging/production migration runbook.
